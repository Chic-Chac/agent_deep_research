# Evaluating and Selecting a Prompt Ensemble for LLM-Generated Issue Labels (Unsupervised + Small Labeled Set)

Scope note: Setting = temperature-0 local LLM rewrites each short text into a 4-12 word stance-neutral "issue question" + has_issue flag; strings are embedded; about 40 source issues form anchor groups; about 130 comment issues attach by cosine + margin. Current metrics: per-item 1-cosine between prompt variants (median ~0.10), cross-prompt ARI 0.58-0.71 at 15 groups, split-half ARI of averaged-embedding partitions 0.71 -> 0.75, node silhouette, placebo-context control. Source provenance: items marked "(verified this session)" were checked against an abstract/full-text page during this research; other classic references are cited from their canonical URL and their numbers come from prior knowledge, so the report writer should treat specific numbers in those as "to re-verify". All examples are synthetic.

## 1. Prompt-sensitivity measurement: metrics and number of prompt variants

### Takeaway
The field has moved from "one prompt, one score" to reporting a distribution over prompt variants. The usual statistics are spread (max-min), mean and SD, worst case, rank stability, and instance-level sensitivity (how much the output for the same item changes across variants). Variant counts run from about 10 (SCORE, Reiss) and 16 (Atreja) to 61-100+ (Promptception, PromptEval), so 3-5 variants is at the thin end. A 2025 result warns that much measured "sensitivity" comes from the scoring method rather than the model. That matters directly because our sensitivity is measured by embedding cosine.

### Cited Findings
- **FormatSpread (Sclar et al., ICLR 2024)**: varies only formatting (separators, casing, spacing, field names) in prompts with the same meaning. Formats are sampled from a grammar of plausible formats, and the paper reports the *spread* (max minus min accuracy) across formats, up to 76 accuracy points for LLaMA-2-13B on some tasks. It estimates spread under a compute budget with a bandit/Thompson-sampling search instead of exhaustively evaluating every format. — [arXiv 2310.11324](https://arxiv.org/abs/2310.11324)
  - Transfer: our prompts should vary along *non-semantic* axes too (field order, JSON vs. line format, the wording of the has_issue instruction), not only paraphrased instructions. Report spread (worst pair) as well as the median, since a median 1-cos of 0.10 can hide a long tail.
- **Mizrahi et al., "State of What Art? A Call for Multi-Prompt LLM Evaluation" (TACL 2024)**: 6.5M instances, 20 LLMs, 39 tasks, using automatically generated and then manually verified instruction paraphrases. Model rankings change across paraphrases. They propose use-case-specific aggregate metrics: MaxP (best paraphrase, for developers tuning one prompt), AvgP (mean over paraphrases, for robustness), and CPS (combined performance score, which mixes peak performance with saturation/robustness). — [arXiv 2401.00595](https://arxiv.org/abs/2401.00595) / [TACL](https://aclanthology.org/2024.tacl-1.52/)
  - Transfer: pick the aggregate to fit the goal. We want a pipeline that is robust to prompt choice, which is closer to AvgP/CPS. Reporting only the best prompt pair (ARI 0.71) is MaxP-style and optimistic.
- **POSIX (Chatterjee et al., EMNLP Findings 2024)**: a label-free index based on the change in a response's log-likelihood when the prompt is swapped for an intent-preserving variant, normalized by response length. Adding even one few-shot exemplar tends to reduce sensitivity, while parameter count and instruction tuning do not reliably reduce it (verified this session). — [arXiv 2410.02185](https://arxiv.org/abs/2410.02185); [ACL Anthology PDF](https://aclanthology.org/2024.findings-emnlp.852.pdf)
  - Transfer: with a local model we have access to log-probs. A POSIX-style score (log p(issue_string_A | prompt_B) vs. log p(issue_string_A | prompt_A)) is a model-internal, embedding-free sensitivity check that does not depend on the embedding model's geometry. It also suggests adding 1-2 synthetic exemplars to each prompt as a cheap stabilizer.
- **ProSA (Zhuo et al., EMNLP Findings 2024)**: the PromptSensiScore (PSS) is the average discrepancy between a model's responses to different prompt variants *of the same instance*, i.e. it is instance-level. Low-PSS (robust) instances have higher decoding confidence (verified this session). — [arXiv 2410.12405](https://arxiv.org/abs/2410.12405); [ACL Anthology](https://aclanthology.org/2024.findings-emnlp.108)
  - Transfer: our per-item 1-cos is already a PSS analogue. Use it as a diagnostic per item: flag high-PSS items (ambiguous or multi-issue comments) and check whether they concentrate near attachment margins. Decoding confidence (mean token log-prob of the issue string) can serve as a cheap proxy.
- **PromptBench / PromptRobust (Zhu et al., 2023)**: adversarial prompt perturbations at character, word, sentence and semantic level across many tasks and datasets. The metric is Performance Drop Rate (PDR). — [arXiv 2306.04528](https://arxiv.org/abs/2306.04528)
  - Transfer: adversarial perturbations are less relevant than natural paraphrases here. PDR-like "drop relative to the reference prompt" is still a useful way to report how far each variant's partition falls from the reference prompt's.
- **"Quantifying Variance in Evaluation Benchmarks" (Madaan et al., 2024)**: separates seed variance (identical setup, different training seeds) from other sources, with bootstrap CIs and a monotonicity check. It recommends continuous rather than discrete metrics to reduce variance. — [arXiv 2406.10229](https://arxiv.org/abs/2406.10229)
  - Transfer: this is the template for a *noise-floor* measurement. Before attributing ARI 0.58-0.71 to prompts, measure ARI when only clustering seed or bootstrap resample changes (see section 2).
- **PromptEval (Polo et al., NeurIPS 2024)**: estimates the full performance distribution (quantiles) across 100 prompt templates on MMLU for about the cost of two single-prompt evaluations (a budget of 1-4x single-prompt cost). It uses an IRT model that shares strength across examples and templates, and also covers best-prompt identification (verified this session). — [arXiv 2405.17202](https://arxiv.org/abs/2405.17202); [NeurIPS 2024](https://neurips.cc/virtual/2024/poster/93925)
  - Transfer: you do not need every prompt on every item. A sparse design (each item rewritten by a random subset of prompts) plus a shared model (item effect + prompt effect) can estimate per-prompt behaviour. At n=170 items, though, running all prompts on all items is cheap and simpler.
- **SCORE (Nalbandyan et al., NAACL 2025)**: 10 semantically similar non-adversarial prompts per dataset. Paraphrasing alone causes accuracy swings up to about 10% on MMLU-Pro (verified via summary this session). — [summary](https://liner.com/review/score-systematic-consistency-and-robustness-evaluation-for-large-language-models)
- **Errica et al., label-free "sensitivity" and "consistency" (arXiv 2406.12334, updated 2025; NAACL 2025)**: *sensitivity* is the normalized entropy of a model's predictions across prompt rephrasings for the same input and needs no labels. *Consistency* measures how uniformly same-class items behave. The stated aim is to find unstable weak spots when ground truth is scarce (verified via overview this session). — [alphaxiv overview](https://alphaxiv.org/overview/2406.12334v4)
  - Transfer: the closest label-free analogue for our has_issue boolean. Compute the per-item entropy of has_issue across prompts, separately from string-level 1-cos.
- **Promptception (EMNLP 2025)**: 61 prompt types, 10 large multimodal models, 3 MCQ benchmarks. Proprietary models were more sensitive to phrasing (verified this session). — [arXiv 2509.03986](https://arxiv.org/abs/2509.03986v1)
- **"Flaw or Artifact? Rethinking Prompt Sensitivity" (Hua et al., EMNLP 2025)**: much of the measured sensitivity comes from heuristic scoring (log-likelihood or rigid string match) that marks correct paraphrased answers wrong. Scoring with an LLM judge cut variance and stabilized rankings (verified via abstract/summary this session). — [arXiv 2509.01790](https://arxiv.org/pdf/2509.01790)
  - Transfer: our 1-cos is a "scorer". The embedding model may treat "Should the city raise bus fares?" vs. "Is a bus fare increase justified?" as distant, or treat two distinct issues sharing vocabulary as close. Calibrate 1-cos against a small set of human same/different judgments (section 4) before reading it as sensitivity.
- **Atreja et al. (ICWSM 2025; arXiv 2406.11980)**: factorial prompt design with 16 prompts per task over 4 CSS tasks and 3 models (362,928 annotations). Minor prompt changes shift label *distributions* substantially, the effects are model- and task-specific, and they are stronger for multi-class tasks. Asking for numeric scores lowered compliance and accuracy (verified this session). — [arXiv 2406.11980](https://arxiv.org/abs/2406.11980v1)
  - Transfer: a factorial design (e.g. 2 x 2 x 2: definition wording x output format x exemplar present) lets you attribute variance to prompt *components*, not just to whole prompts. Track the has_issue positive rate per prompt as a distribution-shift check.

### Inferences
- Common metric families to report for our setting: (a) median and 90th-percentile per-item 1-cos; (b) worst-pair and mean-pair partition ARI/AMI (spread); (c) per-item has_issue entropy; (d) optionally a POSIX-style log-likelihood index. Spread and tail matter more than the median.
- The literature uses 10-100 variants mainly to *estimate a distribution*. An *ensemble used in production* (section 5) can be much smaller. These are two different numbers: one for measurement, one for deployment.

### Gaps
- Exact paraphrase counts per task in Mizrahi et al. and the format-budget sizes in FormatSpread were not re-verified this session.
- I found no paper measuring prompt sensitivity for *open-ended short generations that are then embedded and clustered*. All the benchmarks above score discrete or MCQ outputs, so transfer to free-text issue questions is by analogy.

## 2. Clustering stability without labels: methods, metric caveats at small n, separating prompt vs. algorithm variance

### Takeaway
Classic stability validation (subsample/bootstrap, split-half transfer, consensus/co-association matrices) is well established. Two caveats from the same literature apply directly: stability must be *normalized against a random/null baseline* that depends on k and n, and stability is *not* evidence of correct structure. At n≈40 anchors, ARI/NMI are noisy and chance-correction choices matter. AMI or element-centric similarity plus item-level bootstrap CIs are safer than single ARI numbers.

### Cited Findings
- **Ben-Hur, Elisseeff & Guyon (PSB 2002)**: cluster repeated random subsamples, compare pairs of solutions on their overlapping points, and choose k where the distribution of similarity scores stays concentrated near 1. — [PSB 2002 PDF](https://psb.stanford.edu/psb-online/proceedings/psb02/benhur.pdf)
- **Lange, Roth, Braun & Buhmann, "Stability-based validation of clustering solutions" (Neural Computation 16(6), 2004)**: split data in two, cluster both halves, train a classifier on one half's clustering to predict the other half, and measure disagreement after optimal label matching (Hungarian). Crucially, they *normalize by the instability expected from random labelings with the same k*, because raw instability grows with k. — [doi:10.1162/089976604773717621](https://doi.org/10.1162/089976604773717621)
  - Transfer: our split-half ARI (0.71 -> 0.75) needs the matching null. Compute the same split-half ARI for (i) random partitions with the same group-size distribution and (ii) partitions from a *placebo prompt* or shuffled embeddings. Report stability minus null, not the raw value.
- **von Luxburg, "Clustering Stability: An Overview" (Foundations and Trends in ML 2(3), 2010)**: a review of resampling-based stability for model selection, with its theoretical guarantees and limits. It recommends stability as one heuristic among several, not a validity criterion. — [arXiv 1007.1075](https://arxiv.org/abs/1007.1075)
- **Ben-David, von Luxburg & Pál, "A Sober Look at Clustering Stability" (COLT 2006)**: for large samples, stability is governed by whether the objective has a unique global minimizer. That depends on the *symmetries of the data*, which may be unrelated to the right number of clusters, so stability can be a weak guide for choosing k. A 2010 Machine Learning paper argues stability does not fully "break down" for k-means (verified this session). — [PDF](https://cs.uwaterloo.ca/~shai/sober.pdf); [COLT entry](https://mlanthology.org/colt/2006/bendavid2006colt-sober); [later k-means paper](https://springerlink.bibliotecabuap.elogim.com/doi/10.1007/s10994-010-5177-8)
- **Monti, Tamayo, Mesirov & Golub, Consensus Clustering (Machine Learning 52, 2003)**: resample, recluster, and build a consensus matrix M[i,j] (the fraction of runs in which i and j share a cluster when both are sampled). k is chosen from the consensus CDF / area-under-CDF change. — [doi:10.1023/A:1023949509487](https://doi.org/10.1023/A:1023949509487)
- **Şenbabaoğlu, Michailidis & Li, "Critical limitations of consensus clustering in class discovery" (Scientific Reports 2014)**: consensus clustering produced *apparently stable clusters on randomly generated unimodal data* for a range of k, and common implementations recovered the true k poorly. They propose **PAC** (proportion of ambiguous clustering), the share of item pairs with consensus values in a middle interval such as (0.1, 0.9), where lower is better, and calibrate it against null data (verified this session). — [bioRxiv](https://www.biorxiv.org/content/10.1101/002642v2); [diceR PAC docs](https://rdrr.io/cran/diceR/man/PAC.html)
  - Transfer: a co-association matrix across *prompts* (the fraction of prompts under which two anchors fall in the same group) plus PAC gives a direct "how ambiguous is each anchor pair" score. The specific pairs that are ambiguous are the best candidates for human labeling (section 4). Always compare PAC to a null: embeddings with permuted dimensions, or a placebo prompt.
- **Strehl & Ghosh, Cluster Ensembles (JMLR 3, 2002)**: an NMI-based consensus objective with co-association (CSPA), hypergraph (HGPA) and meta-clustering (MCLA) consensus functions. Fred & Jain's evidence accumulation (TPAMI 2005) clusters the co-association matrix directly. — [JMLR](https://www.jmlr.org/papers/v3/strehl02a.html); [Fred & Jain TPAMI](https://doi.org/10.1109/TPAMI.2005.113)
  - Transfer: two ways to ensemble prompts exist. **Early fusion** (average embeddings across prompts, which is what the team does now) and **late fusion** (cluster per prompt, then consensus over the co-association matrix). Late fusion makes per-prompt disagreement visible and auditable, and the two should be compared.
- **Vinh, Epps & Bailey (JMLR 11, 2010)**: NMI is biased upward when the number of clusters is large relative to n. They propose Adjusted Mutual Information (AMI) with chance correction. — [JMLR](https://www.jmlr.org/papers/v11/vinh10a.html)
- **Romano, Vinh, Bailey & Verspoor, "Adjusting for Chance Clustering Comparison Measures" (JMLR 17, 2016)**: guidance is to use ARI when the reference has large, roughly equal-sized clusters and AMI when it is unbalanced with small clusters. — [JMLR](https://www.jmlr.org/papers/v17/15-627.html)
- **Gates & Ahn, "The impact of random models on clustering similarity" (JMLR 18, 2017)**: ARI/AMI's chance correction assumes a particular random model (usually fixed marginals / permutation). Choosing a different but equally reasonable null can change conclusions. — [JMLR](https://www.jmlr.org/papers/v18/17-039.html)
- **Gates, Wood, Hetrick & Ahn, "Element-centric clustering comparison" (Scientific Reports 9, 2019)**: element-centric similarity gives a *per-element* similarity score, avoids some pair-counting biases, and handles overlapping and hierarchical clusterings (Python package CluSim). — [doi:10.1038/s41598-019-44892-y](https://doi.org/10.1038/s41598-019-44892-y)
  - Transfer: per-element scores show *which anchors* move between prompts, which turns a global ARI of 0.6 into an actionable list. With 40 anchors and 15 groups (mean group size about 2.7, many singletons), ARI is on the "many small unbalanced clusters" side, so add AMI and element-centric similarity.

### Inferences
- **Small-n caveat (explicit):** 40 anchors give only 780 anchor pairs. With 15 groups of about 2-3 items, there are only on the order of 25-40 within-group pairs, so ARI is driven by a few dozen co-clustered pairs and one moved anchor can shift it noticeably. Pairs are not independent (each anchor appears in 39 pairs), so confidence intervals must come from **bootstrapping items (anchors)**, not pairs, and the bootstrap must handle duplicated items (e.g. compare only on unique items, or use subsampling without replacement at 70-80%, as Ben-Hur et al. do).
- **Separating prompt variance from algorithm variance:** use a crossed design. Factor A = prompt (P variants); Factor B = clustering randomness (seeds, item subsample, or k ±2). Compute: (1) the *algorithm floor*: ARI between runs that share a prompt and differ only in seed/subsample; (2) the *prompt effect*: ARI between prompts with the seed held fixed; (3) the *placebo floor*: ARI against a placebo-context prompt. The prompt-attributable instability is roughly the gap between (1) and (2). If (1) is already about 0.7, the 0.58-0.71 cross-prompt ARI is mostly algorithm/geometry noise, not prompt effects. A variance-components model (random effects for prompt, seed and item) formalizes this, in the spirit of generalizability theory.
- Since the LLM runs at temperature 0, there is no within-prompt sampling noise. Sources of variation are prompt, embedding model, clustering algorithm/seed/k, and item sample. Measure each by changing one at a time.
- The split-half rise 0.71 -> 0.75 from averaging embeddings is a 0.04 gain at n≈40. Without a bootstrap CI it may be within noise. Report it with a CI and against the random-partition null of Lange et al.

### Gaps
- I found no published guidance specific to clustering about 40 items into about 15 groups. Most stability theory is asymptotic, and the consensus-clustering evaluations used hundreds of samples.
- I did not verify a published generalizability-theory application to LLM prompt variance. The variance-components suggestion above is an inference.

## 3. Stability vs. validity: avoiding "stably wrong / overly generic", and specificity and coverage metrics

### Takeaway
Several independent results show that stability or agreement can be high while conclusions are wrong. Consensus clustering finds stable clusters in structureless data, stability tracks data symmetries rather than truth, and LLM annotation configurations with high F1 still flip conclusions. In our setting the specific failure is **generic collapse**: a prompt that maps many comments to "Should the policy be changed?" gets low 1-cos and high ARI. Stability must therefore be paired with specificity, distinctiveness and coverage metrics and with a small human-validated check.

### Cited Findings
- **Stable but wrong (clustering)**: consensus clustering yields apparently stable partitions of random unimodal data ([Şenbabaoğlu et al. 2014](https://www.biorxiv.org/content/10.1101/002642v2)), and stability is governed by data symmetries rather than the correctness of k ([Ben-David et al. 2006](https://cs.uwaterloo.ca/~shai/sober.pdf)).
- **Stable but wrong (LLM annotation)**: "LLM hacking" (Baumann, Röttger, Urman et al., arXiv 2509.08825, 2025) replicated 37 annotation tasks from 21 studies with 18 models (13M labels, 2,361 hypotheses). About 31% of hypotheses reached incorrect conclusions with state-of-the-art models and about 50% with small models. Weighted F1 explained only about 7.7% of the variance in hacking risk, so even highly accurate models stay susceptible, and accidental hacking occurs under standard practice (verified via abstract/summaries this session; one Bocconi seminar abstract cites about 20% instead of 31%, so treat the arXiv figure as authoritative). — [arXiv 2509.08825](https://arxiv.org/abs/2509.08825)
  - Transfer: the downstream "conclusion" is the anchor-comment linkage (which comments map to which source issues). Evaluate stability of *that output*, e.g. the share of comments whose attached anchor changes across prompts, not only string similarity.
- **Sensitivity can be a scoring artifact** ([Hua et al., EMNLP 2025](https://arxiv.org/pdf/2509.01790)). The reverse also holds: a lenient scorer (an embedding that maps all policy questions near each other) can manufacture *stability*.
- **Topic diversity (Dieng, Ruiz & Blei, TACL 2020)**: the percentage of unique words among the top-25 words of all topics. It is a simple corpus-level "are the topics distinct" measure. — [TACL](https://aclanthology.org/2020.tacl-1.29/)
- **Hoyle et al., "Is Automated Topic Model Evaluation Broken?" (NeurIPS 2021)**: automated coherence metrics did not reliably track human judgments, especially for neural topic models. Human validation is needed. — [arXiv 2107.02173](https://arxiv.org/abs/2107.02173)
- **Document coverage (Doi, Isonuma & Yanaka, 2024)**: the share of documents containing at least one topic word, plus a factuality check that topic words come from the source vocabulary. LLM-based topic methods had high coherence but *lower document coverage* than baselines (verified this session). — [arXiv 2406.00697](https://arxiv.org/pdf/2406.00697)
- **LLM-as-judge for topic quality (Tan & D'Souza, 2025)**: a "missing themes" count (key themes omitted) and, in a follow-up (*Int. J. on Digital Libraries*, Sep 2025), nine LLM-based metrics across lexical validity, intra-topic soundness, inter-topic structural soundness (redundancy) and document-topic alignment. Evaluator-specific biases affect results, so the choice of judge matters (verified this session). — [arXiv 2502.07352](https://arxiv.org/pdf/2502.07352); [arXiv 2509.07142](https://arxiv.org/abs/2509.07142)
- **Description-as-classifier validity (GoalEx, Wang, Shang & Zhong, EMNLP 2023)**: cluster descriptions are scored by whether an LLM, given only the description, assigns the right documents to it, which tests specificity and coverage operationally. — [arXiv 2305.13749](https://arxiv.org/abs/2305.13749)
- **Validation requirement in CSS**: Reiss (2023) recommends against unsupervised use without comparison to human-annotated data ([arXiv 2304.11085](https://arxiv.org/abs/2304.11085)). Pangakis, Wolken & Fasching (2023) find LLM annotation performance varies by task and argue it "requires validation" against a human-labeled subset ([arXiv 2306.00176](https://arxiv.org/abs/2306.00176)).

### Inferences (specificity/coverage metrics adapted to issue questions; none is an established standard for this exact output)
- **Reverse-retrieval specificity (recommended primary anti-collapse metric):** for each item, embed its issue question and rank all source texts (or all items' source texts) by similarity. Report top-1 / MRR of retrieving its own source. Generic labels ("Should this change?") fail this test, while stable *and* specific labels pass. It is label-free and GoalEx-like.
- **Label distinctiveness:** mean nearest-neighbour 1-cos among the 40 anchor labels, and the number of distinct strings / near-duplicate rate (pairs with 1-cos < τ). Collapse shows up as falling distinctiveness while ARI rises.
- **Partition entropy / effective number of groups:** exp(H(group sizes)). If a prompt raises ARI but cuts the effective number of groups (e.g. one mega-group), that is collapse, not improvement.
- **Lexical genericity:** the share of labels that drop all content words from the source (no noun overlap with the source text), or that match a stoplist of generic templates. This is a cheap synthetic-checkable signal.
- **Attachment coverage:** the share of the 130 comments that clear the margin and attach, and the share of anchors receiving at least 1 comment. Too-generic anchors over-attract comments, which shows as a heavy-tailed attachment count.
- **Composite rule:** accept a prompt or ensemble only if stability (prompt ARI above the algorithm floor) is non-inferior *and* specificity (reverse-retrieval MRR, distinctiveness) is non-inferior *and* human pairwise F1 (section 4) is non-inferior.

### Gaps
- I found no published "specificity score" for LLM-generated *question-form* labels. The topic-model specificity measures above are word-list based and transfer only loosely.
- I found no paper formally showing that stability-based prompt selection is biased toward generic outputs in LLM generation. The concern is well-founded by analogy (sections above) but not directly documented.

## 4. Small labeled set: pairwise same/different judgments, metrics, sample size, agreement, active pair selection, using constraints

### Takeaway
Pairwise same-issue/different-issue labels are a natural fit. They evaluate both the embedding scorer and the partition via pairwise precision/recall/F1 (or Rand on labeled pairs), and B-cubed is the metric with the best formal properties when item-level gold clusters exist. Choose pairs actively (ambiguous co-association / near-margin pairs plus a random stratum for unbiased estimates), measure human agreement with Krippendorff's alpha (≥0.80 reliable, ≥0.667 tentative), and use the labels mainly to *evaluate/calibrate* (thresholds, margin, k, prompt choice), not to train.

### Cited Findings
- **Viswanathan, Gashteovski, Lawrence, Wu & Neubig, "Large Language Models Enable Few-Shot Clustering" (arXiv 2307.00524, 2023; later published in TACL 2024 per the ACL Anthology, venue not re-verified this session)**: LLMs are used before clustering (generating keyphrases that are embedded and concatenated, which is the strongest approach overall: best on 3/5 datasets), during clustering (the LLM as a pseudo-oracle labelling about 20,000 must-link/cannot-link pairs for PCKMeans, with pairs chosen by Explore-Consolidate for text, or as the closest distinct pairs in embedding space for entity canonicalization), and after clustering (correcting the 500 least-confident points, which gave small gains and often wrong reassignments, at 55-57% accuracy on two datasets). Metrics: pairwise/macro/micro P/R/F1 and NMI/accuracy. Their estimate: a true human oracle needs at least about 2,500 labeled pairs before PCKMeans adds value for entity canonicalization, and human pair labelling runs about 3 pairs per minute (verified this session). — [arXiv HTML](https://arxiv.org/html/2307.00524)
  - Transfer: (a) "keyphrase expansion" closely parallels our approach (LLM-rewritten text embedded), and their result supports it. (b) Using pairwise labels to *constrain* clustering needs thousands of pairs, far beyond a small human set, so use human pairs for *evaluation/calibration*. (c) An LLM pairwise judge (different prompt/model from the generator) could pre-label many pairs, with humans auditing a subset.
- **ClusterLLM (Zhang, Wang & Shang, EMNLP 2023)**: triplet questions to the LLM ("which of two candidates is closer to the anchor") with *entropy-based selection of ambiguous anchors* and candidates drawn from the two nearest clusters. This beat random triplet sampling, and random triplets could even hurt. Granularity is chosen by asking pairwise questions over a cluster hierarchy and picking the level most consistent with the answers. Average cost was about $0.6 per dataset across 14 datasets (verified this session). — [arXiv 2305.14871](https://arxiv.org/abs/2305.14871); [ACL Anthology](https://preview.aclanthology.org/setup/2023.emnlp-main.858)
  - Transfer: (a) select human pairs where the anchor's cluster assignment is uncertain (high PAC / near margin), comparing against its 2 nearest groups. (b) Use the "pick k / granularity most consistent with pairwise answers" idea to choose the number of anchor groups (e.g. 12 vs. 15 vs. 20) from the human labels.
- **Basu, Banerjee & Mooney, "Active Semi-Supervision for Pairwise Constrained Clustering" (SDM 2004)**: the Explore (farthest-first traversal to find one point per cluster) then Consolidate (query points against found clusters) strategy for choosing informative pairs. — [PDF](https://www.cs.utexas.edu/~ml/papers/semi-sdm-04.pdf)
- **Davidson, Wagstaff & Basu, "Measuring Constraint-Set Utility for Partitional Clustering Algorithms" (PKDD 2006)**: constraint sets vary in *informativeness* (how much they tell the algorithm beyond what it already does) and *coherence* (how much they agree with each other in the metric). Some constraint sets *decrease* accuracy. — [Springer](https://doi.org/10.1007/11871637_15)
- **Amigó, Gonzalo, Artiles & Verdejo, "A comparison of extrinsic clustering evaluation metrics based on formal constraints" (Information Retrieval 12, 2009)**: of the common extrinsic metrics, only B-cubed precision/recall satisfies all four constraints (homogeneity, completeness, rag bag, cluster size vs. quantity). Pair-counting and purity metrics each violate at least one. — [doi:10.1007/s10791-008-9066-8](https://doi.org/10.1007/s10791-008-9066-8)
- **Krippendorff's alpha thresholds**: α ≥ .800 for reliable data, and .667 ≤ α < .800 only for tentative conclusions. — [Krippendorff, "Computing Krippendorff's Alpha-Reliability"](https://repository.upenn.edu/asc_papers/43/)
- **Prompts-as-coders reliability**: Reiss (2023) found pairwise Krippendorff's α across 10 instruction variants ranged 0.24-0.70 (mean 0.43). Repeated runs at low temperature reached α > 0.9, and majority-pooling 10 repetitions raised agreement from 0.75 to 0.91 between temperature settings (verified this session). — [arXiv 2304.11085](https://arxiv.org/abs/2304.11085)

### Inferences
- **Metrics on labeled pairs:** for a set of human-labeled pairs, the pipeline predicts "same" if both items land in the same anchor group (or, for comment-anchor pairs, if the comment attaches to that anchor). Report pairwise precision, recall and F1 on "same", plus the per-prompt ROC-AUC of raw cosine as a scorer-quality check (does 1-cos separate same from different?). With item-level gold groups for a subset, compute B-cubed.
- **How many pairs (arithmetic, not from a source):** a proportion's 95% CI half-width ≈ 1.96·sqrt(p(1-p)/n). For p≈0.8, n=100 gives ±0.08, n=200 ±0.055, n=400 ±0.04. Telling apart two prompts whose pairwise F1 differs by about 0.05 therefore needs a few hundred pairs, and a *paired* comparison (same pairs scored under both prompts, McNemar-style) needs fewer. Human cost at about 3 pairs/min ([Viswanathan et al.](https://arxiv.org/html/2307.00524)) means 300 pairs is about 100 minutes per annotator.
- **Pair sampling design:** random pairs among 40 anchors are mostly "different" (low base rate of "same"), which wastes labels. Use stratified sampling: (i) a near-margin / high-PAC stratum (most informative for decisions), (ii) a high-confidence-same stratum, (iii) a high-confidence-different stratum, (iv) a small uniform-random stratum. Use inverse-probability weights when estimating overall precision/recall so the active selection does not bias the estimate.
- **Agreement:** have 2-3 annotators label an overlapping subset (e.g. 100 pairs). Report Krippendorff's α for the humans *and* treat each prompt as an additional "coder" (prompt-vs-human α), following the Reiss/Barrie framing. If human α < 0.667, the "same issue" definition itself is underspecified, and no prompt can be judged on it.
- **Overfitting caveat:** with few pairs, tuning the margin, k and prompt choice on the same pairs overfits. Hold out about 30% of pairs, or use cross-validation over pairs grouped by item.

### Gaps
- I found no study giving a principled minimum number of human pairwise judgments for *evaluating* (as opposed to constraining) a clustering. The numbers above are standard binomial arithmetic.
- The TACL 2024 venue for Viswanathan et al. comes from prior knowledge and was not re-verified this session (the arXiv page lists no venue).

## 5. Choosing the number and kind of ensemble members

### Takeaway
Ensemble-selection literature consistently says to select on **quality and diversity jointly** (each alone is unreliable), use **greedy forward selection with a held-out check**, and expect **diminishing returns**: gains in self-consistency-style aggregation flatten after several to tens of samples, and moderate diversity beats maximal diversity in cluster ensembles. For a small ensemble of 3-5 prompts, an exhaustive or greedy search over subsets, scored by a composite of stability-above-floor, specificity and human pairwise F1, plus leave-one-prompt-out analysis, is feasible and defensible.

### Cited Findings
- **Caruana, Niculescu-Mizil, Crew & Ksikes, "Ensemble Selection from Libraries of Models" (ICML 2004)**: greedy forward stepwise selection from a model library, *with replacement*, optimizing a target metric on a hillclimb set. Sorted initialization and bagged selection reduce overfitting to the selection set. — [PDF](https://www.cs.cornell.edu/~caruana/ctp/ct.papers/caruana.icml04.icdm06long.pdf)
- **Fern & Lin, "Cluster Ensemble Selection" (SDM 2008 / Statistical Analysis and Data Mining 1(3), 2008)**: selecting a subset of clusterings from a library by **quality and diversity jointly** (methods JC, CAS, CH) significantly beat using the full ensemble. Selecting by quality alone or diversity alone was not consistently helpful (verified this session). — [author PDF](https://web.engr.oregonstate.edu/~xfern/ensem_select.pdf); [doi:10.1002/sam.10008](https://doi.org/10.1002/sam.10008)
  - Transfer: quality can be measured without labels by average NMI/AMI to the other members (Fern & Lin use the sum of NMI to all library members as quality), and diversity by pairwise (1 - NMI). With human pairs, replace quality by pairwise F1.
- **Hadjitodorov, Kuncheva & Todorova, "Moderate diversity for better cluster ensembles" (Information Fusion 7(3), 2006)**: ensembles with *moderate* diversity yielded better consensus than those with maximal diversity. — [doi:10.1016/j.inffus.2005.01.008](https://doi.org/10.1016/j.inffus.2005.01.008)
  - Transfer: do not add a prompt just because it disagrees most (a placebo or broken prompt is maximally "diverse"). The target is prompts that are individually good and disagree only on genuinely ambiguous items.
- **Self-consistency (Wang et al., ICLR 2023)**: majority vote over sampled reasoning paths. Accuracy rises with the number of samples, with most of the gain early and flattening toward the tens (they plot up to 40). — [arXiv 2203.11171](https://arxiv.org/abs/2203.11171)
- **Ask Me Anything (Arora et al., ICLR 2023)**: aggregates multiple imperfect prompt reformulations with weak supervision. It models prompts as noisy voters with *varying accuracies and dependencies* rather than equal-weight majority vote. — [arXiv 2210.02441](https://arxiv.org/abs/2210.02441)
  - Transfer: prompts are correlated "annotators". Two near-paraphrase prompts add less than two structurally different ones. Estimate prompt-prompt dependency (cross-prompt AMI) and down-weight redundant members, or in early fusion just avoid near-duplicates.
- **Prompt Stability Score (Barrie, Palaiologou & Törnberg, arXiv 2407.02039, v3 May 2026)**: adapts intra- and inter-coder reliability to prompts. *Intra*-prompt stability is the same prompt repeated, *inter*-prompt stability is across paraphrases. The `promptstability` Python package was tested on 6 datasets / 12 outcomes (about 3.1M rows). The exact computation and paraphrase counts were not visible on the abstract page (verified this session). — [arXiv 2407.02039](https://arxiv.org/abs/2407.02039)
  - Transfer: at temperature 0 intra-prompt stability is trivially 1, so the informative quantity is inter-prompt stability, i.e. our cross-prompt agreement, ideally reported as α so it is comparable to CSS norms.
- **Törnberg, "Best Practices for Text Annotation with LLMs" (arXiv 2402.05129, 2024; Sociologica)**: recommends a written codebook-style prompt, validation against human labels, transparency, and testing robustness to prompt variation. — [arXiv 2402.05129](https://arxiv.org/abs/2402.05129)
- **Ziems et al., "Can Large Language Models Transform Computational Social Science?" (Computational Linguistics 50(1), 2024)**: across 25 CSS benchmarks, LLMs did not beat fine-tuned models on classification but were useful for generative/explanatory tasks and as collaborators with humans. They recommend human-in-the-loop validation. — [ACL Anthology](https://aclanthology.org/2024.cl-1.8/)

### Inferences
- **Practical selection recipe for P≈5-8 candidate prompts:** enumerate all subsets of size 2-4 (at most a few hundred subsets, cheap to score). For each subset build the early-fused (averaged-embedding) partition and compute: (a) bootstrap stability minus algorithm floor, (b) specificity (reverse-retrieval MRR, distinctiveness, effective number of groups), (c) human pairwise F1 on held-out pairs if available. Pick the smallest subset within one bootstrap SE of the best composite (a "one-SE rule" to avoid overfitting at n≈40).
- **Diminishing-returns curve:** plot split-half ARI (and pairwise F1) vs. ensemble size m=1..P, averaged over random orderings of prompts. If m=3 reaches within noise of m=P, stop at 3.
- **Leave-one-prompt-out:** for the chosen ensemble, drop each member and recompute metrics. A member whose removal *raises* specificity or F1 is harmful. A member whose removal changes nothing is redundant.
- **Kind of members:** vary along axes that are orthogonal by design (definition wording, output format, exemplar presence, abstraction-level instruction), following the factorial approach of [Atreja et al.](https://arxiv.org/abs/2406.11980v1) and the format axes of [FormatSpread](https://arxiv.org/abs/2310.11324), rather than K near-paraphrases.

### Gaps
- I found no paper that specifically selects *prompt* ensembles for embedding-then-cluster pipelines. Evidence comes by analogy from model ensembles (Caruana), cluster ensembles (Fern & Lin; Hadjitodorov et al.) and answer-aggregation prompting (AMA, self-consistency).
- The exact saturation point in self-consistency figures (e.g. where the curve flattens per task) was not re-verified this session.

## 6. Concrete offline check protocol (~40 anchors, ~130 comment issues)

### Takeaway
A one-day, mostly label-free protocol, with an optional 300-pair human set: establish noise floors first, then measure prompt effects above them, guard against generic collapse with specificity metrics, and use a small stratified human pair set to calibrate and break ties. Every number gets an item-bootstrap CI and is compared to a null.

### Cited Findings
- Normalize stability by a random/null baseline ([Lange et al. 2004](https://doi.org/10.1162/089976604773717621)). Use PAC on co-association matrices with null calibration ([Şenbabaoğlu et al. 2014](https://www.biorxiv.org/content/10.1101/002642v2)). Prefer AMI/element-centric measures for many small, unbalanced clusters ([Romano et al. 2016](https://www.jmlr.org/papers/v17/15-627.html); [Gates et al. 2019](https://doi.org/10.1038/s41598-019-44892-y)). Select members on quality and diversity jointly ([Fern & Lin 2008](https://web.engr.oregonstate.edu/~xfern/ensem_select.pdf)). Choose informative pairs by entropy/ambiguity ([ClusterLLM 2023](https://arxiv.org/abs/2305.14871)). Use humans for evaluation rather than constraints at small scale ([Viswanathan et al. 2023](https://arxiv.org/html/2307.00524)).

### Inferences (protocol; synthetic placeholders only)
**Step 0: Fix everything except one factor at a time.** Freeze the embedding model, normalization, clustering algorithm, k (15) and attachment margin. Keep P candidate prompts (5-8), built factorially (e.g. definition wording x output format x 1 synthetic exemplar present/absent) plus 1 placebo-context prompt.

**Step 1: Noise floors (label-free).**
- (a) Algorithm floor: for one prompt, 50 runs with different seeds and 80% anchor subsamples. Report the median and IQR of pairwise ARI/AMI on overlapping anchors.
- (b) Random floor: ARI of random partitions with the same group-size distribution (approximately 0 by construction, but report the *spread* at n=40).
- (c) Placebo floor: ARI between the placebo prompt and each real prompt.
- (d) Embedding floor (optional): the same strings under a second embedding model, to check whether the "sensitivity" is scorer-driven ([Hua et al. 2025](https://arxiv.org/pdf/2509.01790)).

**Step 2: Prompt effect (label-free).**
- Cross-prompt AMI/ARI matrix (P x P) with the seed fixed. Prompt-attributable instability = algorithm floor minus cross-prompt agreement. Report the worst pair, the mean and a 95% item-bootstrap CI (resample anchors, recluster, recompute).
- Per-item metrics: 1-cos across prompts (median, p90, max), has_issue entropy across prompts, and element-centric per-anchor similarity. List the top 10 most unstable anchors.
- Co-association matrix across prompts x seeds. Compute PAC(0.1, 0.9) and compare it to PAC on a null (e.g. embeddings with permuted dimensions or shuffled anchor-text assignment).
- Downstream stability: the share of the 130 comments whose attached anchor (or "unattached" status) changes across prompts. This is the decision-relevant quantity ([Baumann et al. 2025](https://arxiv.org/abs/2509.08825)).
- Optional: a POSIX-style log-likelihood index using the local model's log-probs ([Chatterjee et al. 2024](https://arxiv.org/abs/2410.02185)).

**Step 3: Anti-collapse / specificity (label-free).** For each prompt and each candidate ensemble:
- reverse-retrieval MRR (issue question -> own source text among all 170 sources);
- mean nearest-neighbour 1-cos among the 40 anchor labels and the near-duplicate rate;
- effective number of groups exp(H) and the largest group's share;
- attachment coverage (the share of 130 comments attached; Gini of comments-per-anchor);
- has_issue positive rate (a distribution-shift check à la [Atreja et al.](https://arxiv.org/abs/2406.11980v1)).

Flag any prompt or ensemble whose stability rises while specificity falls as "collapse".

**Step 4: Ensemble size and composition.**
- Diminishing-returns curve: split-half ARI and specificity vs. m=1..P (average over 20 random prompt orderings).
- Exhaustive scoring of subsets of size 2-4, comparing early fusion (averaged embeddings) and late fusion (consensus over co-association).
- Selection: maximize stability-above-floor subject to specificity non-inferiority (e.g. MRR not more than 1 bootstrap SE below the best single prompt). Pick the smallest subset within one SE of the best.
- Leave-one-prompt-out on the chosen subset.

**Step 5: Small human pairwise set (optional but recommended; about 300 pairs).**
- Draw strata from Steps 2-3: about 120 ambiguous pairs (consensus 0.1-0.9 or within ±margin of the attachment threshold), about 60 confident-same, about 60 confident-different, and about 60 uniform-random anchor-anchor or comment-anchor pairs. Store the sampling probabilities.
- 2 annotators label all pairs and a third labels 100. Report Krippendorff's α, and if α < 0.667, revise the "same issue" definition before using the labels.
- Split 70/30 grouped by anchor. On the 30% held out, report the weighted pairwise P/R/F1 of each candidate ensemble's "same group / attached" decision, the ROC-AUC of raw cosine for same vs. different, and a paired comparison (McNemar on discordant pairs) between the top two ensembles.
- Use the 70% only to calibrate the margin and choose k (e.g. 12/15/20, the ClusterLLM-style "most consistent granularity").

**Step 6: Reporting.** One table per candidate (rows) with: algorithm floor, cross-prompt AMI [CI], PAC vs. null, comment-attachment flip rate, reverse-retrieval MRR, effective number of groups, and human pairwise F1 [CI]. State explicitly that with n≈40 anchors, differences in ARI/AMI below about the bootstrap SE (likely several hundredths) are not interpretable.

### Gaps
- The thresholds in this protocol (strata sizes, the one-SE rule, PAC interval 0.1-0.9, about 300 pairs) are reasoned defaults drawn from the cited methods. None has been validated for this exact pipeline, and they should be checked on the team's own data.
- I found no published benchmark of reverse-retrieval specificity for LLM-generated issue questions, so its adequacy as an anti-collapse guard is an untested inference.
