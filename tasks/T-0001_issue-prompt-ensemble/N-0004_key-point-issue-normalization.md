# Key Point Analysis, Claim Normalization, and Stance-Neutral Issue Framing: Evidence for Canonical Issue-String Generation

Scope note: 15 tool calls were used. Items tagged **[verified]** were checked against a fetched page or search snippet this session. Items tagged **[prior knowledge, not re-fetched]** come from well-known papers whose URLs I am confident about but whose details I did not re-check here; the report writer should treat their specific numbers as softer. Examples are synthetic.

## Q1. Key Point Analysis (KPA): how key points are made concise, non-redundant, matchable; stance conditioning; multi-prompt/ensembles; quality judgment

### Takeaway
KPA does **not** use stance-neutral strings. Its key points are short **stance-bearing claims**, and every step (generation, matching, quantification) runs **per topic and per stance**. Concision and matchability come from hard filters (single sentence, token cap, no leading pronoun, quality score) plus **match-score-based redundancy removal**. LLM-era KPA moved to "cluster first, then summarize each cluster" or "generate many candidates, then select or deduplicate them with a matcher". I found **no published multi-prompt ensemble for key point generation**. The only robustness evidence is temperature and run variance, mostly for LLM *evaluators*. Quality is judged on **coverage** and **redundancy**, plus sometimes faithfulness and specificity. The closest analogue to an "issue question" format is QANA, which generates questions from comments and matches them by embedding cosine; closed yes/no questions worked best.

### Cited Findings
- **Original KPA (Bar-Haim et al., ACL 2020, "From Arguments to Key Points")**: introduced KPA and the ArgKP dataset of argument–key point match labels. Expert-written key points are short claims given per topic (a debate motion) and per stance, and arguments are matched only to key points of the same stance [prior knowledge, not re-fetched; ~24K labeled pairs over 28 topics] — [ACL Anthology 2020.acl-main.371](https://aclanthology.org/2020.acl-main.371)
  - *Transfer:* KPA's "string" is the pro or con claim *inside* a fixed topic. Our "issue question" sits one level up: it plays the role of KPA's *topic/motion*, not its key point. So KPA matching results say more about our comment→anchor matching *within* an issue (if stance is ever added) than about issue canonicalization itself.
- **Automatic KP extraction pipeline ("BarH", Bar-Haim et al. EMNLP 2020, as summarized by Altemeyer et al. 2025)**: candidates exclude multi-sentence arguments, arguments longer than a token threshold *n*, and arguments that start with pronouns. A quality scorer keeps candidates above *tq*. A match scorer assigns each remaining argument to its best candidate, and candidates are ranked by match count. **Redundancy removal:** a candidate is dropped if its match score with a higher-ranked candidate exceeds *tm*. All of this runs **per topic and stance** [verified via Altemeyer et al.] — [arXiv 2503.00847](https://arxiv.org/html/2503.00847v4); original: [Bar-Haim et al. EMNLP 2020, 2020.emnlp-main.3](https://aclanthology.org/2020.emnlp-main.3) [prior knowledge]
  - *Transfer:* Concrete recipes for canonical strings: (1) a length cap and "no pronoun / self-contained" filter, which suits our 4-12 word limit; (2) **dedup by a matcher, not by string identity**: drop an issue string whose match or cosine to an already-kept, higher-support issue is above a threshold. This is the KPA-native way to collapse prompt-variant strings.
- **KPA-2021 shared task (Friedman et al., ArgMining@EMNLP 2021)**: two tracks, key point **matching** and key point **generation/quantification**, on the ArgKP-2021 dataset. Annotators labeled argument–KP pairs as match, no-match or undecided. Code and terms are in IBM's `KPA_2021_shared_task` repo [verified]. Evaluation used mAP under "strict" and "relaxed" treatment of undecided pairs [prior knowledge] — [ACL Anthology 2021.argmining-1.16](https://aclanthology.org/2021.argmining-1.16); [arXiv 2110.10577](https://arxiv.org/pdf/2110.10577)
  - *Transfer:* The strict/relaxed split is a useful template for our gold matching labels: allow an "undecided" label for comment issues that are partly about the anchor issue, and report both.
- **Reviews: "Every Bite Is an Experience" (Bar-Haim et al., ACL-IJCNLP 2021)**: adapts KPA to business reviews with "Collective Key Point Mining" for better extraction, adds sentiment analysis, and selects good KP candidates using review volume and metadata. Reports good results without domain-specific annotation, and better results with human supervision [verified, abstract level] — [arXiv 2106.06758](https://arxiv.org/abs/2106.06758)
  - *Transfer:* "Collective mining" means picking the KP candidates that many items match, rather than trusting one item's phrasing. That is a *selection-over-pool* strategy, and it maps directly onto choosing a canonical issue from a pool of prompt-ensemble outputs.
- **Li et al., ACL 2023 ("Do You Hear The People Sing? KPA via Iterative Clustering and Abstractive Summarisation")**: a two-step framework. Neural-topic-model clustering (BERTopic with SBERT, UMAP and HDBSCAN) uses **iterative clustering that reassigns unclustered/outlier arguments**, and then FLAN-T5 summarizes each cluster into a key point. It also proposes **set-based** evaluation (Soft-Precision/Recall/F1) instead of per-sentence ROUGE. Reported gains of up to ~14 points absolute; sources differ on which metric [verified] — [arXiv 2305.16000](https://arxiv.org/abs/2305.16000); [ACL 2023 long.786](https://preview.aclanthology.org/credits/2023.acl-long.786); pipeline details from [Altemeyer et al.](https://arxiv.org/html/2503.00847v4)
  - *Transfer:* The **cluster-then-name** order makes the canonical string a function of the cluster, not of one text. A cheap version for us: generate per-text issues (with any prompt ensemble), cluster the embeddings, then have the LLM write *one* canonical issue question per cluster. Prompt variance at the per-text level then matters only through cluster membership.
- **Altemeyer et al. 2025 ("Argument Summarization and its Evaluation in the Era of LLMs", arXiv 2503.00847)**: compares (a) LLM zero-shot generation of **12–20 candidates** fed into BarH or SMatchToPr selection, (b) **MCArgSum** (agglomerative clustering on match scores, with an LLM summarizing each cluster), and (c) LLM end-to-end generation of **4–8 summaries with an explicit instruction to avoid overlap**. Weighted score (α=2/3 on coverage) is highest for LLM end-to-end with Qwen3-32B: 0.923 on ArgKP21 and 0.899 on Debate. BarH with Qwen3-32B candidates scores 0.900 and 0.880, and USKPM (Li et al. 2023) 0.800 and 0.833. **No ensemble or multi-prompt approach**; one uniform prompt across LLMs plus a temperature sweep [verified] — [arXiv 2503.00847](https://arxiv.org/html/2503.00847v4)
  - *Transfer:* "Generate many candidates, then select with a matcher" is competitive with end-to-end LLM summaries. That supports a design where an ensemble *over-generates* issue strings and a deterministic selector (support count or centrality) picks the canonical one.
- **Quality criteria and metric reliability (Altemeyer et al. 2025)**: human evaluation uses **coverage** and **redundancy**, with inter-annotator Pearson 0.697 and 0.722. Li et al.'s Soft-Score correlates weakly with human coverage (best 0.265 across topics, 0.402 within). Khosravani et al.'s (2024) Coverage-Score does better (up to 0.541 across, 0.698 within). **LLM-judge metrics do best** (coverage 0.767 across and 0.803±0.115 within, redundancy 0.852 and 0.824±0.055). LLM judge scores were averaged over **10 runs**, and at temperature 0.2 the **std reached about ±0.23 for redundancy**, a direct sign of run-to-run instability [verified] — [arXiv 2503.00847](https://arxiv.org/html/2503.00847v4)
  - *Transfer:* (1) Judge an issue inventory on **coverage** (are all texts matched to some issue?) and **redundancy** (are near-duplicate issues present?), not on string overlap with a reference. (2) If an LLM judge is used, average several runs; single-run judgments are noisy.
- **Khosravani et al. 2024** (cited in Altemeyer): a clustering-based, extractive method that picks the most representative argument per cluster with a supervised scorer, and introduces an automatic Coverage-Score focused on "exhaustiveness" [verified only via Altemeyer's description] — [arXiv 2503.00847](https://arxiv.org/html/2503.00847v4)
- **PAKPA (Tang, Zhang, Dinh, Cambria, ACL 2024, "Prompted Aspect Key Point Analysis for Quantitative Review Summarization")**: argues that sentence-level KP generation yields **unfaithful and overlapping** key points and **inaccurate prevalence counts**. It fixes this by first doing prompted **aspect-based sentiment extraction**, then **clustering comments by shared aspect+sentiment**, then prompted KP generation per cluster. Reports SOTA on Yelp and SPACE with little annotated data [verified, abstract level] — [ACL Anthology 2024.acl-long.576](https://aclanthology.org/2024.acl-long.576); [arXiv 2407.14049](https://arxiv.org/html/2407.14049v1)
  - *Transfer:* This is the strongest evidence that **an intermediate structured, normalized representation (aspect) before free-text naming reduces overlap and duplication**. Our analogue is to extract a short *aspect/topic slot* (e.g., "AI safety standards / government role") first, cluster or match on it, and only then render the 4-12-word question.
- **QANA (Fukuma et al., arXiv 2404.18371, 2024)**: uses LLMs (GPT-3.5, GPT-4) to generate **questions** from each comment ("closed-ended questions that capture similar or opposing viewpoints"), builds a bipartite comment–question graph whose edges are **embedding cosine** (multilingual-E5, text-embedding-3-large), and ranks questions by centrality (PageRank and degree beat betweenness and closeness). For key point matching, **closed (yes/no) GPT-4 questions with text-embedding-3-large were best**, roughly comparable to top supervised KPA-2021 systems, zero-shot and at linear cost. With E5, question generation helped and paraphrasing hurt. With text-embedding-3-large, paraphrasing helped and GPT-3.5 open questions did worse than raw arguments. For generation, the top 10 questions (GPT-4, te-3-large, PageRank) covered 85% of reference key points [verified; exact mAP values only in figures] — [arXiv 2404.18371](https://arxiv.org/html/2404.18371)
  - *Transfer:* This is the closest published evidence for our "issue question" design. (1) A **closed yes/no question** ("whether X should Y") is a good matching key under embedding cosine. (2) The benefit depends on the **embedding model × question-type** combination, so our ensemble choice should be validated with *our* embedder. (3) **Centrality over a pool of generated questions** is a principled way to pick canonical issues from ensemble outputs.
- **ArgCMV (Gurjar et al., EMNLP 2025)**: a KP-extraction benchmark of ~12K arguments from real online debates (ChangeMyView) over 3K+ topics. Existing KPA methods transfer poorly from ArgKP21 [verified, abstract level] — [ACL Anthology preview 2025.emnlp-main.1110](https://preview.aclanthology.org/credits/2025.emnlp-main.1110); [arXiv 2508.19580](https://arxiv.org/html/2508.19580v1)
  - *Transfer:* Conversational, noisy text (like viewer comments) is harder than curated ArgKP arguments. Expect methods tuned on clean "note block" text to degrade on comments.

### Inferences
- KPA's machinery for making strings matchable is almost entirely **post-hoc**: filtering, matcher-based dedup, clustering before naming, and centrality-based selection. Prompt wording is a smaller lever. For our prompt ensemble, this suggests ensemble members should feed a **selection/consolidation step** rather than being averaged at the string level.
- Because KPA always conditions on stance, its matchers are trained to *separate* pro and con. If we reuse KPA-style matchers (e.g., SMatchToPr-type contrastive models), they may penalize comment–anchor pairs that discuss the same issue with opposite stance. That is the opposite of what our issue-level matching wants.

### Gaps
- "Hear me out" (Li et al. 2023) could not be located under that title. The Li et al. ACL 2023 KPA paper is "Do You Hear The People Sing?", which is probably the intended reference. "Khosla et al. 2023, Exploring the potential of LLMs for key point generation" was **not found**. The likely intended works are Khosravani et al. 2024 (exhaustiveness/coverage) or general LLM-argumentation surveys. Its existence should be treated as unverified.
- No paper found that **ensembles multiple prompts** for KP generation or measures **prompt-wording sensitivity** of generated key points. The only variability evidence is temperature and run variance of LLM judges (Altemeyer). This is a thin-evidence area.
- Exact candidate token caps in Bar-Haim 2020/2021 (values of *n*) were not retrieved.

## Q2. Claim normalization / claim detection: canonical claim strings and the effect of prompt variation

### Takeaway
Claim normalization (ClaimNorm) rewrites noisy posts (~94 tokens) into one concise, self-contained, check-worthy **stance-bearing factual statement** (~14 tokens). It is evaluated by **METEOR against a single human reference**. Evidence on prompt variation is anecdotal but consistent: elaborate CoT prompts produce **framing preambles** ("The post claims that…") that hurt reference matching. Gold references are themselves inconsistent for near-duplicate posts. A strong practical trick is **retrieval-then-reuse**: when a new post is close enough to a known one, copy its existing normalization instead of generating a new one.

### Cited Findings
- **Sundriyal, Chakraborty, Nakov, Findings of EMNLP 2023 ("From Chaos to Clarity: Claim Normalization to Empower Fact-Checking")**: defines ClaimNorm as decomposing complex, noisy posts into straightforward "normalized claims". Introduces the **CLAN** dataset (6K+ posts with normalized claims) and **CACN**, which combines chain-of-thought, claim check-worthiness estimation and in-context learning with LLMs, and beats several baselines [verified, abstract level] — [ACL Anthology 2023.findings-emnlp.439](https://aclanthology.org/2023.findings-emnlp.439); [arXiv 2310.14338](https://arxiv.org/abs/2310.14338)
- **CLEF-2025 CheckThat! Lab, Task 2 (claim normalization)**: 20 languages, split into 13 supervised and 7 zero-shot tracks, scored by **METEOR**; normalized claims feed retrieval and verification [verified via overview abstract and task page] — [arXiv 2503.14828](https://arxiv.org/pdf/2503.14828.pdf); [Task page](https://checkthat.gitlab.io/clef2025/task2)
- **DS@GT participant paper (Pramov, Ma, Patel, CLEF 2025 working notes)**: posts average ~94 tokens and normalized claims ~14. Many gold claims are **low-context** (mean BERTScore recall vs post ≈0.15 on English train). The method: **retrieve the nearest train/dev post; if cosine exceeds a per-language threshold (0.60 English; 0.80–0.90 for most others), reuse its normalization**; otherwise prompt GPT-4o-mini with the top-3 retrieved examples. The detailed **CACN prompt produced preambles like "The post claims that…"** that hurt METEOR and were hard to strip, so they moved to a simpler in-context prompt. **Near-duplicate posts across splits have different gold normalizations** (different wording and detail). Test METEOR examples: English 0.452 (rank 2), Spanish 0.608 (rank 1); zero-shot languages 0.116–0.317. No numeric prompt ablations [verified] — [arXiv 2508.17402](https://arxiv.org/html/2508.17402v1)
  - *Transfer:* (1) **Template leakage** is the claim-normalization version of our phrasing drift. Our analogue is a fixed frame like "whether …". Enforce it with a strict output schema and strip it before embedding if it inflates similarity. (2) **Retrieve-and-reuse** maps directly onto anchor matching: if a comment's raw text, or its first-pass issue, is above a cosine threshold to an existing anchor, assign the anchor's canonical issue string rather than generating a new one. Our margin rule already does this, but it could be applied *before* generation to remove variance. (3) Even human gold is inconsistent, so string-level agreement is a poor target. Measure **assignment consistency** (same cluster or anchor) instead.
- **AKCIT-FN (CheckThat 2025)**: combined fine-tuned small LMs with LLM prompting and placed top-3 in 15 of 20 languages [verified, search snippet only] — [GitHub AKCIT-FN/checkthat2025_normalization](https://gh.r-mj.com/AKCIT-FN/checkthat2025_normalization); [CheckThat overview](https://checkthat.gitlab.io/clef2025/session_1/0_CheckThat_CLEF_2025_long_task_overviews.pdf)

### Inferences
- ClaimNorm targets a **stance-bearing, verifiable** statement, while our target is a **stance-neutral question**. The transferable part is the pipeline hygiene (single self-contained proposition, no meta-framing, length compression, and reuse of an existing canonical form), not the output format.
- A METEOR-against-one-reference setup penalizes legitimate paraphrase. That supports evaluating our ensemble by downstream **cluster/anchor agreement** (e.g., ARI or assignment stability across prompts) rather than by lexical similarity of strings.

### Gaps
- I did not retrieve the CheckThat 2025 overview's aggregate analysis of which prompt strategies won, or any systematic prompt-variation ablation. Evidence that prompt changes alter normalized claims is **anecdotal** (DS@GT's preamble observation).
- Query rewriting for fact-check retrieval (e.g., CheckThat claim-retrieval tasks) was not covered in this session.

## Q3. Issue / frame / topic-stance representations: stance-neutral targets, frames, agenda codes, aspects, and deliberation formats

### Takeaway
Across stance detection, framing and deliberation, the **stance-neutral object is the "target/topic"** (a noun phrase or a motion), and stance is a separate label. Open-target stance detection shows LLMs can *generate* such targets, and that generating the target first and then the stance is a workable decomposition. Implicit targets are much harder. Framing and agenda schemes give **fixed, coarse, issue-general taxonomies** that can act as an abstraction anchor. Deliberation systems use **stance-bearing statements** (Polis comments, Habermas Machine group statements, Project Debater motions) that people vote on. None uses a "whether X" neutral question as the canonical unit, though a debate *motion* is functionally a yes/no proposition.

### Cited Findings
- **Open-Target Stance Detection (Akash, Fahmy, Trabelsi; arXiv 2409.00222, revised to v5 Dec 2024 and later)**: the target is neither seen in training nor given as input. GPT, Gemini, Llama and Mistral are compared against Target-Stance Extraction (TSE) under a **two-step** (generate target, then stance) and a **one-step joint** prompt. LLMs beat TSE at target generation for both explicit and implicit targets. **Both tasks degrade when the target is implicit.** The paper proposes a target-quality metric that correlates with human judgment. The abstract's claims about LLM stance performance on explicit targets changed between v1 and later versions [verified]. Venue: one aggregator says ACL 2024, which conflicts with the Aug 2024 arXiv date, so **venue unconfirmed** — [arXiv 2409.00222](https://arxiv.org/abs/2409.00222); [HTML v5](https://arxiv.org/html/2409.00222v5)
  - *Transfer:* Our issue question is essentially an **open "target" plus an implied yes/no proposition**. The OTSD finding that implicit targets are hard predicts that **viewer comments** (often reactive, with implicit targets like "this is insane") will produce the most variable issue strings. Consider giving comments the video's anchor issues or context as candidate targets. That turns open target generation into *target selection*, which is more stable.
- **Target-Stance Extraction (TSE)** is the pre-LLM baseline that extracts targets from a predefined target list; OTSD removes that list [verified via Akash et al. description] — [arXiv 2409.00222](https://arxiv.org/html/2409.00222v5)
  - *Transfer:* A "closed list" mode (match to anchors) vs an "open" mode (new issue) is exactly our anchor vs new-cluster decision.
- **Media Frames Corpus (Card et al., ACL 2015)**: annotates news on immigration, smoking and same-sex marriage with **15 issue-general framing dimensions** from the Policy Frames Codebook (e.g., economic, morality, fairness/equality, legality/constitutionality, policy prescription, public opinion) [prior knowledge, not re-fetched] — [ACL Anthology P15-2072](https://aclanthology.org/P15-2072)
  - *Transfer:* A framing dimension is **orthogonal to stance and to issue**. "Whether governments should set AI safety standards" could be framed economically or in terms of safety. Prompts that vary "perspective" may silently inject frame words ("economic cost of…"), producing frame-specific rather than issue-level strings. Instruct ensemble members to *exclude* frame and justification content from the issue string, or keep frame as a separate field.
- **Comparative Agendas Project (CAP)**: a cross-national policy-topic coding scheme with ~20 major topics and ~200+ subtopics, used to code bills, speeches and media by issue regardless of position [prior knowledge, not re-fetched] — [comparativeagendas.net](https://www.comparativeagendas.net/)
  - *Transfer:* CAP is a ready **coarse abstraction anchor**. One ensemble member (or a post-step) could assign a CAP-style major topic, used as a blocking key or consistency check for issue clustering.
- **Argument aspects (Reimers et al., ACL 2019, "Classification and Clustering of Arguments with Contextualized Word Embeddings")**: introduced an argument-similarity corpus (UKP ASPECT) labeling whether two same-topic arguments address the same **aspect**, and evaluated argument clustering with BERT/ELMo [prior knowledge for corpus details; paper verified as relevant] — [arXiv 1906.09821](https://arxiv.org/pdf/1906.09821); [ACL P19-1054](https://preview.aclanthology.org/fix_video/P19-1054.pdf)
  - *Transfer:* "Aspect" (sub-issue within a topic) is the granularity just below our issue question. Aspect-similarity annotation, which is stance-agnostic, is the closest existing gold-standard format for "same issue regardless of side".
- **Habermas Machine (Tessler et al., Science 386(6719), Oct 2024, "AI can help humans find common ground in democratic deliberation")**: an LLM mediator for UK small groups on divisive issues (Brexit, immigration, minimum wage, climate). A generative model drafts many candidate **group statements**. A personalized reward model predicts each participant's agreement, and a simulated election selects the winner. Critiques are incorporated through the same generate-and-select loop. AI statements were preferred over human mediators' statements, and positions converged [verified via secondary sources; Science text not fetched] — [Science DOI 10.1126/science.adq2852](https://www.science.org/doi/10.1126/science.adq2852); [arXiv 2601.05904 discussion](https://arxiv.org/pdf/2601.05904)
  - *Transfer:* The **"over-generate, then select by predicted acceptability across viewpoints"** pattern is a principled consensus mechanism for choosing one string from an ensemble. For neutrality, a selection criterion could be "a pro-reader and a con-reader would both accept this as a fair statement of the question", scored by an LLM judge. Note that HM statements are long, stance-bearing paragraphs, not neutral questions.
- **IBM Project Debater (Slonim et al., Nature 2021)**: debates are on **motions** in a fixed proposition format ("We should ban X" / "We should subsidize Y"). ArgKP topics use the same motion format, and stance is pro or con relative to the motion [prior knowledge, not re-fetched] — [Nature s41586-021-03215-w](https://www.nature.com/articles/s41586-021-03215-w)
  - *Transfer:* A motion is a **canonical yes/no proposition**, and "whether we should X" is its question form. The IBM line shows that a single fixed syntactic template ("We should [policy verb] [object]") supports large-scale matching. A fixed template for our issues (e.g., "whether [actor] should [action] [object]") would reduce surface variance across prompts.
- **Polis / Talk to the City**: Polis participants write short statements and others vote agree/disagree/pass; opinion groups come from vote matrices, not text. Talk to the City uses LLMs to extract claims and cluster them into topics [prior knowledge, not re-fetched] — [Polis (Small et al. 2021, Recerca)](https://doi.org/10.6035/recerca.5516); [Talk to the City repo](https://github.com/AIObjectives/talk-to-the-city-reports)

### Inferences
- The consistent design across fields is **issue/target (neutral) ⟂ stance (label) ⟂ frame (lens)**. Our 4-12-word issue question collapses issue and an implied proposition into one string, which is reasonable. Ensemble members that vary *perspective* or *framing* risk leaking frame or stance into the string. Members varying *abstraction* change granularity, which is a different axis (Q5). These should not be treated as interchangeable "diversity".
- Turning comment issue generation from open to *constrained by anchors* (TSE-like) is the single most evidence-backed variance reducer for implicit-target texts.

### Gaps
- "Tweets2Stance" (Li et al. 2023 per the brief) was not verified this session; the attribution may be wrong.
- No study found that compares neutral-question vs claim vs noun-phrase **targets** for downstream stance or clustering accuracy.
- Polis / Talk to the City details are prior knowledge only. No peer-reviewed evaluation of Talk to the City's claim-string consistency was found.

## Q4. Question vs claim vs topic-noun-phrase phrasing for embedding similarity; stance invariance of embeddings

### Takeaway
Generic sentence embeddings are largely **stance-invariant**: they cluster pro and con texts on the same topic together. This is a known failure for opinion mining, but **desirable for issue clustering**. QANA gives direct evidence that **closed yes/no questions are effective matching keys under cosine**, but the effect depends on the embedder. I found no controlled study of "whether X" vs "X is good" vs "X" (noun phrase) for embedding similarity; that is a **gap**.

### Cited Findings
- **"I love pineapple on pizza != I hate pineapple on pizza: Stance-Aware Sentence Transformers for Opinion Mining" (EMNLP 2024)**: standard sentence transformers are good at grouping topically similar texts but **struggle to separate opposing viewpoints on the same topic**. Pro- and anti-abortion tweets are grouped together because they are topically similar. The authors add a stance-aware loss to push contradictory pairs apart [verified] — [ACL Anthology 2024.emnlp-main.1171](https://aclanthology.org/2024.emnlp-main.1171.pdf)
  - *Transfer:* Strong support for using **off-the-shelf (non-stance-tuned) embedders** on stance-neutral issue strings. Neutral phrasing plus a stance-invariant embedder means pro and con comments land on the same anchor. Avoid stance-aware fine-tuned embedders for this step. Also, even if some ensemble members leak stance ("governments must regulate AI"), a generic embedder will partly absorb it, though how much is unmeasured.
- **Reuver et al., ArgMining 2021 ("Is Stance Detection Topic-Independent and Cross-topic Generalizable?")**: topic, class (pro/con) and their interaction all affect cross-topic stance performance [verified, snippet] — [ACL Anthology 2021.argmining-1.5](https://preview.aclanthology.org/setup/2021.argmining-1.5)
- **Same Side Stance Classification (Stein et al. / Körner et al.)**: frames stance as "do two arguments take the same side?", a pairwise, topic-relative formulation [verified, snippet] — [arXiv 2004.11163](https://fugumt.com/fugumt/paper_check/2004.11163v1_enmode)
- **QANA (2024)**: question vs paraphrase vs raw argument as matching keys. With multilingual-E5, generated questions helped and paraphrases hurt. With text-embedding-3-large, paraphrases helped and GPT-3.5 open-ended questions underperformed raw arguments. **Closed GPT-4 questions with text-embedding-3-large were best** [verified] — [arXiv 2404.18371](https://arxiv.org/html/2404.18371)
  - *Transfer:* (1) The question form is a viable canonical format. (2) **Closed** questions beat open ones for matching. Our "whether X should Y" is a closed question in indirect form, which matches the winning condition. (3) Generator quality matters (GPT-4 > GPT-3.5), so for a *local* LLM, expect weaker question quality. That favors more structure (templates, aspect slots) over free-form prompts.
- **Asymmetric query/passage embedders**: E5-family models are trained with "query:" / "passage:" prefixes, and instruction-tuned embedders (e.g., INSTRUCTOR) condition on task instructions. Comparing two *questions* is a symmetric task, so issue-to-issue cosine should use the symmetric setting (same prefix on both sides) [prior knowledge, not re-fetched] — [E5, Wang et al. 2022, arXiv 2212.03533](https://arxiv.org/abs/2212.03533)
  - *Transfer:* If the team uses E5/BGE-style models, embed every issue string with the **same** prefix (both "query:" for symmetric similarity). Mixing raw comments ("passage") with issue questions ("query") changes the cosine distribution and the margin thresholds.

### Inferences
- Shared template tokens ("whether", "should") add a constant component to all issue embeddings, which can **compress cosine range** and make margins less discriminative. Stripping the template before embedding, or embedding only the content span, is worth an ablation. This is an inference with no direct evidence, but DS@GT's "preamble hurts METEOR" result is the lexical analogue.
- Because generic embedders conflate pro and con, a stance-bearing ensemble member (claim framing) may be *less harmful* for clustering than expected. It would still harm canonical string choice if it wins the selection step, so selection should prefer the neutral member.

### Gaps
- **No controlled study found** that compares embedding similarity of "whether X", "X is good / X is bad" and the bare noun phrase "X" for the same content. This is the central thin-evidence point; the team should run its own ablation (synthetic example: "whether cities should ban cars downtown" vs "banning cars downtown improves cities" vs "downtown car bans").
- No study found on how negation and polarity flips affect cosine for *question-form* strings specifically.

## Q5. Granularity / abstraction level: general vs specific issues and hierarchies

### Takeaway
KPA handles granularity by **organizing key points into a specificity hierarchy** (Cattan et al. 2023) rather than picking one level, and by **aspect-level grounding** in reviews (PAKPA). Framing and agenda schemes supply fixed coarse levels. For our setting this suggests generating at **two levels** (coarse issue + specific issue) with an explicit entailment relation, rather than letting abstraction vary freely across ensemble members.

### Cited Findings
- **Cattan, Eden, Kantor, Bar-Haim, ACL 2023 ("From Key Points to Key Point Hierarchy: Structured and Expressive Opinion Summarization")**: introduces the task of organizing key points into a **hierarchy by specificity**, framed as a **textual entailment graph** (a specific KP entails a more general one). Releases **ThinkP**, a benchmark of KP hierarchies for business and product reviews. The best pairwise relation predictor uses **directional distributional similarity with weak supervision** and beats strong baselines. Code and data: IBM/kpa-hierarchy [verified] — [ACL Anthology 2023.acl-long.52](https://aclanthology.org/2023.acl-long.52); [arXiv 2306.03853](https://arxiv.org/pdf/2306.03853); [GitHub](https://github.com/ibm/kpa-hierarchy)
  - *Transfer:* Abstraction-varying ensemble members produce strings at different levels (synthetic: "whether AI should be regulated" ⊃ "whether governments should set AI safety standards" ⊃ "whether frontier labs need pre-release safety audits"). These should be **linked by directional entailment, not merged by cosine**, because cosine is symmetric and will either over-merge or split them arbitrarily. A directional check (an NLI model or an LLM asking "does A imply B is at issue?") can build a two-level issue tree, with anchors matched at the specific level and rolled up for reporting.
- **PAKPA (ACL 2024)**: grounding key points in **entity aspects** prevents overlap and gives accurate counts [verified, abstract level] — [ACL Anthology 2024.acl-long.576](https://aclanthology.org/2024.acl-long.576)
  - *Transfer:* Fixing the aspect (object of the issue) first, then generating the question, pins the abstraction level to the aspect inventory.
- **Altemeyer et al. 2025**: end-to-end LLM summarization was constrained to **4–8 key points** with a no-overlap instruction, and candidate generation to **12–20** candidates. The **number of outputs implicitly sets granularity** [verified] — [arXiv 2503.00847](https://arxiv.org/html/2503.00847v4)
  - *Transfer:* When the LLM names a cluster, telling it the target inventory size (or the sibling issues) controls abstraction better than adjectives like "general" or "specific".
- **Media Frames Corpus (15 dimensions) and CAP (~20 major topics)**: fixed coarse levels [prior knowledge] — [P15-2072](https://aclanthology.org/P15-2072); [comparativeagendas.net](https://www.comparativeagendas.net/)

### Inferences
- Of the ensemble axes the team proposes (perspective, question vs claim, abstraction), **abstraction is the one most likely to break cosine-margin matching**, because it creates systematic parent/child pairs with intermediate cosine that fall inside the margin band. Keep abstraction as a separate, explicitly labeled output level, not as an ensemble "vote".
- A defensible ensemble design consistent with this literature: N prompts → per-text candidate issues → cluster or deduplicate with a matcher (BarH-style threshold) → choose the canonical string by support or centrality (Every Bite "collective mining", QANA PageRank, Habermas-style selection) → link levels with a directional entailment check (Cattan). Evaluate with coverage, redundancy and assignment stability (Altemeyer), not string overlap (CheckThat/DS@GT reference inconsistency).

### Gaps
- No study found that measures how prompt instructions about abstraction ("general" vs "specific") shift the level of LLM-generated key points or issues.
- No direct evidence on choosing granularity for *cross-source matching* (video anchors vs comments). KPA works within one corpus and stance.
